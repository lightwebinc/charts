{{- if $c.advertise }}
Announced fetch URL: {{ include "arcade-bridge.announceUrl" . }}
  Check this is what MERKLE-SERVICE'S CONTAINERS can dial (not loopback, and
  not a v6-only address unless their network routes v6). Every subtree and
  block announcement carries it; if it is unreachable or wrong, announcements
  keep succeeding, no fetch ever arrives, and every failed fetch charges this
  bridge's fetch-health breaker under peer id {{ $c.peerId | default "arcade-bridge" | quote }}.

WARNING: config.advertise is EMPTY and mode is not sink. The bridge exits 2 at
startup. Set it to the base URL merkle-service can dial for fetches, WITHOUT
the API prefix (the announced URL is advertise + config.apiPrefix):
  --set config.advertise=http://<address-merkle-service-can-dial>:{{ include "arcade-bridge.port" $c.retrievalListen }}
If merkle-service resolves this k8s cluster's DNS, that address is:
  http://{{ $full }}-retrieval.{{ .Release.Namespace }}.svc.cluster.local:{{ include "arcade-bridge.port" $c.retrievalListen }}
{{- end }}
{{- if not $c.kafka }}

WARNING: config.kafka is EMPTY and mode is not sink. The bridge exits 2 at
startup. It is a list, joined into the single comma-separated -kafka flag:
  --set config.kafka[0]=<merkle-service-kafka>:19092
Remember the advertised-listener rule: the broker must advertise an address
this pod can dial back.
